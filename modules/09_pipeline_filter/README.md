# 模块 09：管道-过滤器（音视频处理链）

> 对应实现：`pipeline.h`（IFilter 接口版 + Pipeline 函数式版），`main.cpp`（音频处理链 + 函数式组合）。

## 来源

**管道-过滤器（Pipe-Filter）**：架构模式（非 GoF 23，属 POSA 一系）。Unix 管道（`cat | grep | sort`）是原型，FFmpeg filter graph、编译器前端（词法→语法→语义→代码生成）、音视频处理链都是它的实例。思想：**把处理拆成独立步骤，数据流经管道，每一步只做一件事**。

关联 GoF：管道-过滤器与责任链都是"链式"，但责任链是请求沿链传递、可中途终止；管道是数据流逐级变换、必须走完。装饰器也是链，但装饰器是动态叠加行为，管道是固定数据处理流。

## 用法

```cpp
// 接口版：过滤器继承 IFilter<T>，管道串联
class LowPass : public IFilter<std::vector<float>> { ... };   // 实现 process/name
FilterChain<std::vector<float>> chain;
chain.add(&lp).add(&gain).add(&gate);
auto out = chain.process(signal);

// 函数式版：lambda 直接组合
Pipeline<std::vector<float>> p;
p.add([](std::vector<float> v) { ...; return v; }).add(...);
auto r = p.run(signal);
```

## 使用场景

- **音视频处理链**：解码 → 滤镜（降噪/增益/均衡）→ 编码 → 封装，每个环节独立可替换可测试（★Filmora 场景）；
- **图像/信号管线**：采集 → 预处理 → 特征提取 → 输出；
- **编译器前端**：词法分析 → 语法分析 → 语义分析 → 中间代码；
- **数据清洗/ETL**：抽取 → 清洗 → 转换 → 加载，各级可单独调试。

## 原理（内存层）

### 数据流逐级变换

```
输入帧 → [过滤器1] → [过滤器2] → ... → [过滤器n] → 输出帧
         只处理一帧     只处理一帧             只处理一帧
```

- 每级是一份独立代码（可单测、可替换）；数据以值传递（`T process(T)`），级间无共享状态 → 天然可并行（不同帧可进不同级/不同线程）；
- 调用链：接口版是**继承 + vptr/vtable**——每个过滤器对象带隐藏 vptr（8B），`process` 调用 = 查 vtable + 间接跳转（运行时多态）；函数式版是 **std::function 类型擦除**——lambda 进 SBO 缓冲或上堆，调用走函数指针间接跳转（模块 01 mini_function 的内核）；
- 沿链用 `std::move(input)` 传递 → 176KB 的信号帧全程零拷贝；
- 代价：**每级一次移动 + 延迟累加**（总延迟 = 各级延迟之和），调试要逐级看数据。

### 接口版 vs 函数式版（同一模式的两种实现）

| | 接口版 IFilter | 函数式 Pipeline |
|---|---|---|
| 多态机制 | 继承 + vptr/vtable | std::function 类型擦除 |
| 定义过滤器 | 写一个类 | 写一个 lambda |
| 过滤器对象内存 | vptr(8B) + 成员 | std::function(SBO~32B) |
| 适用 | 过滤器有身份（类型/日志/生命周期） | 简单变换、快速组合 |

## 现代 C++ 最佳实践

- **过滤器保持纯函数**：输入帧 → 输出帧，不持有跨帧状态（有状态也要显式声明）——可测、可并行；
- **用值传递 + move**：帧用 `std::move` 沿管道传递，避免每级拷贝（本模块 `chain.process` 内部 `std::move(input)`）；
- **函数式 Pipeline 优先于接口版**（现代工程）：lambda 组合零继承零虚调用，接口版留给"过滤器需要类型标识/生命周期托管"的场景；
- **过滤器互不知晓**：不要在过滤器里直接依赖下一个过滤器，替换/增删只改链装配处。

## 面试要点

- **Q1：管道-过滤器和责任链的区别？** 管道是数据流：每级必须处理、逐级变换、可并行；责任链是请求流：沿链传递、可中途终止（handler 返回 true 即停）、适合解耦"谁处理"。
- **Q2：管道-过滤器的优缺点？** 优：松耦合（级间零依赖）、可复用、可单测、可并行（fan-out）；缺：每级拷贝/延迟累加、调试要逐级看、级数多时管线笨重。
- **Q3：接口版和函数式版怎么选？** 接口版：过滤器有身份（日志/类型/生命周期）、需要运行时多态扩展；函数式版：简单变换、lambda 组合、零继承零虚调用。现代 C++ 倾向函数式 + 必要时接口。
- **Q4：管道和装饰器的区别？** 装饰器是运行时动态叠加行为（一层套一层，可任意增减），管道是固定的数据处理流（级序确定、数据逐级变换）。
- **Q5：管道怎么并行？** 级内并行（一帧拆多块并行处理）或级间流水线（不同帧并行走不同级，生产者-消费者模型）；本模块接口版数据值传递无共享状态，天然适合并行。
- **Q6：和你 Qt 项目的结合？** Filmora 的滤镜/导出处理链、QMediaPlayer 解码链，本质都是管道-过滤器——讲"项目里滤镜处理链就是管道-过滤器"是加分项。
