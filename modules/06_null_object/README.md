# 模块 06：空对象（Null Object）——用空行为替代空指针判空

> 对应实现：`null_object.h`（`IRenderer` 抽象 + `NullRenderer` 单例空对象 + `OpenGLRenderer` 真实实现 + `MediaPipeline` 使用方 + `createRenderer` 工厂）。

## 来源

- **Null Object**：Bobby Woolf 提出（收录于《Pattern Languages of Program Design 3》），GoF 23 之外的常见补充模式。
- 核心思想：把"没有/空"建模成一个**行为为空但真实存在**的对象，而不是 `nullptr`。判空逻辑在构造期兜底一次，之后所有调用点零判空。
- 本质是策略模式的退化形态：空对象就是"空策略"（什么都不做的策略）。

## 用法

```cpp
MediaPipeline silent;                 // 默认构造 → 内部兜底为 NullRenderer
silent.render();                      // 无需判空，静默执行

OpenGLRenderer gl;
MediaPipeline withGl(&gl);            // 注入真实实现
withGl.render();                      // 正常绘制

IRenderer& r = createRenderer("vulkan");   // 工厂：未知后端 → 空对象
r.drawFrame(1);                       // 安全调用，永不崩
```

## 使用场景

- **可空后端/插件/驱动**：渲染器、解码器、网络传输——没有真实实现时静默降级，而不是到处判空；
- **工厂失败降级**：配置错误/后端不可用 → 返回空对象而非 `nullptr`，调用方永远不用处理空；
- **日志系统**：生产环境注入"空日志器"（什么都不写），开发环境注入真日志器——同一接口切换；
- **链式/组合调用**：builder、visitor、装饰链里某环节为空，用空对象保持链不断；
- **Qt 视角**：Qt 的惯用风格是 `isNull()` 让调用方判空（QPixmap、QImage、QString 都是），空对象是把判空内聚到对象内部的另一种风格——两者对比是面试常考点。

## 原理（内存层）

### 空对象单例的存储

```
NullRenderer::instance() → 函数内 static 局部对象
  存储期：静态存储期（.bss/.data 段），程序启动即存在，退出时销毁
  分配：零堆分配（不走 new），全程序只有一个实例
  构造：私有化 → 外部无法复制/新建，"空"的语义唯一
```

### 判空的消除（指令层）

```
不用空对象（每个使用点）：
  if (renderer_)  renderer_->drawFrame(id);   // 每个调用点一个分支
  else            /* 空分支处理逻辑，N 处各写一遍 */

用空对象：
  renderer_->drawFrame(id);                    // 零分支
  判空只发生在构造期一次：r ? r : &NullRenderer::instance()
```

分支消除的收益：减少分支预测失败、消灭"漏判空"这一类 bug（空分支逻辑 N 处重复，必然有写漏的）。

### 空对象的一次调用成本

```
renderer_->drawFrame(id)
  = 一次虚函数间接跳转（vtable 查表）+ 空函数体
  与真实实现的调用开销完全相同——"空"不更贵，只是没有行为
```

### 空对象 vs std::optional

| | 空对象 | std::optional |
|---|---|---|
| 语义 | "值永远有，只是行为为空" | "值可能没有" |
| 调用方式 | 直接调用，零检查 | 每次用前检查 `has_value()` |
| 适合 | 接口/策略/后端抽象 | 局部"可能无值"的返回值 |
| 关系 | 消除判空 | 显式判空 |

## 现代 C++ 最佳实践

- 空对象做成**单例 + 不可变**：无状态、私有构造、`static` 局部实例；
- 空对象接口方法**全部空实现**（`{}`），保持"调用即安全"的契约；
- 不拥有所有权的注入用裸指针/引用，所有权用 `unique_ptr`——空对象通常是静态对象，**不能 delete**，工厂返回引用最干净；
- 工厂/默认构造负责兜底，调用方保持零判空；
- 警惕副作用：空对象会**静默吞掉错误**——生产环境里应配合日志/监控区分"正常空"与"异常空"（可给空对象加 `isNull()` 查询位供上层决策）；
- 与策略/状态模式组合：策略集合里天然包含"空策略"，状态机里"空状态"同理。

## 面试要点

- **Q1：空对象模式解决什么问题？** 消除散落在各调用点的判空分支，把"没有"建模为行为为空但真实存在的对象。判空集中到构造期一次。
- **Q2：空对象和空指针的区别？** 空指针是"没有对象"，每次使用都要判空；空对象是"有对象但行为为空"，直接调用安全。语义从"可能不存在"变成"总是存在"。
- **Q3：空对象和 std::optional 取舍？** optional 保留"可能没有"语义，调用方必须检查；空对象消灭检查。接口/策略/后端用空对象，局部可能无值的返回值用 optional。
- **Q4：空对象和策略模式什么关系？** 空对象是策略的特例——空策略。策略接口可以有多个实现，其中一个实现"什么都不做"，就是空对象。
- **Q5：空对象的缺点？** 静默吞错：真实错误（配置错误、后端加载失败）被伪装成"正常空"，问题被掩盖。缓解：空对象提供状态查询 + 上层日志/监控。
- **Q6：Qt 里怎么体现？** Qt 惯用 isNull() 风格（调用方判空），如 QPixmap、QImage；空对象是内聚判空的另一种风格。QModelIndex() 无效索引、QVariant invalid 有类似"空也是合法值"的思想。
