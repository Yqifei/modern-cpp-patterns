# 模块 07：对象池 + QThreadPool（实例复用 / 线程复用）

> 对应实现：`object_pool.h`（泛型 `ObjectPool<T>`：acquire/release + unique_ptr 借用语义）、`main.cpp`（DbConnection 计数对比 + QThreadPool 线程复用演示）。

## 来源

- **Object Pool**：GoF 之外的补充模式（创建型）。核心：复用实例，避免反复创建/销毁的高昂成本。经典场景：数据库连接池、线程池、网络连接池、渲染缓冲池。
- **QThreadPool**：Qt 官方的线程池（QtCore）。全局实例 `globalInstance()` 复用线程执行 `QRunnable`/`QtConcurrent` 任务，避免"每任务建线程"的创建开销与线程风暴。
- 与工厂模式的区别（面试必问）：工厂每次 `new` 返回**新实例**；池优先**复用**，只有池空才新建。

## 用法

```cpp
ObjectPool<DbConnection> pool(
    [] { return std::make_unique<DbConnection>(0); }, 3);   // 预建 3 个

auto conn = pool.acquire();        // 有空闲就复用，池空才新建
conn->id = 7;                      // 借出期间调用方持有
pool.release(std::move(conn));     // 归还：回到空闲列表

// QThreadPool：提交任务，线程复用
QThreadPool pool;
pool.setMaxThreadCount(2);
pool.start(new PoolTask);          // 任务排队，线程池按容量执行
pool.waitForDone();
```

## 使用场景

- **创建代价大的对象**：数据库连接（TCP 握手 + 认证）、线程（系统调用 + 内核栈）、渲染缓冲、加密上下文；
- **复用频率高且数量可控**：连接、buffer、worker 的借还次数远高于创建次数；
- **限制并发资源**：连接池上限 = 数据库能承受的连接数；`QThreadPool::setMaxThreadCount` = 机器核数/N 倍；
- **Qt 视角**：`QThreadPool::globalInstance()` 是 QtConcurrent 的后端；网络模块的连接复用、QRhi 的资源池同类思想。

## 原理（内存层）

### 对象池的内部结构

```
ObjectPool<T>
  ├─ idle_：vector<unique_ptr<T>>   空闲实例列表（堆上对象，生命周期由池托管）
  ├─ creator_：工厂回调（唯一的新建入口）
  └─ mtx_：互斥锁（多线程借还安全）
```

- **借用 = 所有权转移**：`acquire()` 把 unique_ptr 从空闲列表 `move` 出来交给调用方——借出期间池不拥有；
- **归还 = 交回所有权**：`release()` 把 unique_ptr 放回空闲列表——对象本体**不重建**，只有控制块/指针的搬运；
- **复用收益**：10 次借用若串行且峰值 1，预建 3 个后构造次数 = 3（而不是 10）——省下的是构造/析构的堆分配与初始化成本；
- **池空策略**：本模块无上限池（池空直接新建兜底）；生产级可加信号量控制上限 + 等待/拒绝语义。

### 线程池的复用本质

```
每任务建线程：6 个任务 = 6 次 pthread_create + 6 次 join
             （每次含内核栈分配、调度器登记——毫秒级开销）

QThreadPool（2 线程）：线程只创建 2 个，之后反复执行任务
             任务排队，空闲线程取任务执行——线程上下文零重建
```

- 线程创建开销：系统调用 + 内核栈（默认 8MB 虚拟）+ 调度器登记，高频任务场景下是明显的固定成本；
- `QThreadPool` 内部：`QThread` 队列 + 任务队列 + 条件变量（空闲线程阻塞等待任务）——线程数封顶 `maxThreadCount`，任务超出排队；
- 演示证据：6 个任务、2 个线程，线程 ID 只有 2 个不同值，耗时 ≈ 串行的 1/2。

## 现代 C++ 最佳实践

- **unique_ptr 表达借用**：借出期间所有权清晰，归还即 `move` 回池；实例析构自动交还逻辑可包成 RAII 借据类；
- **归还时重置状态**：实例可能被借出方污染（`conn->id = 7`）——`release` 前重置到"出厂状态"，否则下一个借用人拿到脏状态（最常见 bug）；
- **池大小规划**：下限 = 稳态并发需求（预建），上限 = 资源上限（数据库连接数/核数）；无上限池只适合"创建便宜、复用收益一般"的场景；
- **线程安全**：`mutex` 保护空闲列表；生产级可用无锁队列或 `std::mutex + 条件变量`；
- **配合信号量实现有界池**：`std::counting_semaphore` 控制最大借用数，超过则阻塞等待——这是池的完整形态；
- **QThreadPool 注意**：`QRunnable` 不设 autoDelete 需手动管理；长任务别占满线程池（会饿死其他任务）；`globalInstance()` 默认 maxThreadCount = 核数。

## 面试要点

- **Q1：对象池和工厂模式的区别？** 工厂每次创建新实例；池优先复用空闲实例，池空才调工厂兜底。池是"工厂 + 缓存 + 所有权管理"。
- **Q2：什么对象适合池化？** 创建代价大（连接握手、线程创建）、复用频率高、数量可预测且需要受控（数据库连接上限）。创建便宜的小对象池化反而浪费管理成本。
- **Q3：QThreadPool 怎么复用线程？** 线程池持有固定数量线程（maxThreadCount），空闲线程阻塞等任务；任务提交进队列，线程取任务执行——线程本体不销毁重建，只换任务上下文。
- **Q4：池的归还要注意什么？** 重置状态到出厂值：残留的脏数据会泄漏给下一个借用者。借出期间所有权归调用方（unique_ptr），归还即交回。
- **Q5：无上限池和有上限池？** 无上限：池空即新建（本模块），适合创建便宜的兜底场景；有上限：借用超限时等待或拒绝（信号量），保护下游资源不被打爆。
- **Q6：线程池的 maxThreadCount 怎么定？** 计算密集型 = 核数；I/O 密集可适当放大。太小利用率低，太大会线程切换开销反超收益。
